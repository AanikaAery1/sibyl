# Step 6 — Phased roadmap: chair position (2026-10-10)

Inputs: `docs/BRIEF.md`; `docs/council/DECISIONS.md` (D1–D40); `discover/STEP1-UNDERSTANDING.md` and `discover/sprint-prioritizer.md` (Step 1 lanes, ~75 dev-day Phase 1 estimate, demo script); `architect/ARCHITECTURE.md`; `datamodel/DATAMODEL.md` + amendments in `api/SYNTHESIS.md` and `ml/ML.md` §10; `api/API.md`; `ml/ML.md`.

## Chair position
1. **Three phases, each ending in something demonstrable.**
   - **Phase 1 — "Governed failover on localhost"** (the Step 7 build): docker-compose stack; registry + capture policy onboarding; gateway (OpenAI-compatible) + Python SDK + OTLP ingest; explainable health score + rules R1–R9/L1–L7; automatic failover/handoff state machine with tier gating, undo/hold, kill switch, approvals; operator queue; mandatory verdicts; hash-chained audit + anchors + `sibyl audit verify`; erasure crypto-shred; `sibyl-sim` with the 28 scenarios and per-tier gates; demo tenants meridian/northstar/sandbox. Exit = the demo script runs end-to-end and every CRITICAL harness gate passes.
   - **Phase 2 — "First design partner"**: cloud migration (D4/D14: managed Postgres, S3, Helm, off-host backup first), notifications (email/Slack/Teams webhooks), `/v1/messages`, TypeScript SDK, sidecar gateway, learned layer in shadow then promotion (D36/D37), LLM-as-judge opt-in, customer-run drills (D38), per-agent SLO targets, external security assessment before first paying tenant (D18).
   - **Phase 3 — "Sellable product"**: region-pinned stacks/residency promise, SOC 2 readiness, ITSM integrations, billing/metering, compliance report packs (EU AI Act, NIST AI RMF, ISO 42001), marketplace of continuity templates.
2. **Phase 1 is sized honestly.** Re-estimate against the Step 4/5 surface (≈110 routes, 76 tables, 28 scenarios), not the Step 1 guess. If it exceeds ~20 working days wall-clock with parallel lanes, propose explicit cut lines (what moves to Phase 1.5) rather than silently trimming.
3. **Build lanes with strict file ownership** for Step 7 (max 6 per wave, TDD inside each lane, worktree isolation where lanes collide), mapped to repo directories. Interfaces/schemas frozen in a wave 0 before lanes fan out.
4. **Milestones are demo-able increments** (e.g. M1 ingest→registry→health visible; M2 detected failover + audit; M3 prediction + approvals + queue; M4 erasure + harness gates green). Each milestone has acceptance tests from `ml/qa-expert.md` and `api/API.md`.
5. **Risks carried forward** from Steps 1–5 get an owner, a trigger and a mitigation; single-operator (D18) and zero-budget (D10) constraints are explicit inputs, not afterthoughts.

Members: sprint-prioritizer (leads: phase scopes, Phase 1 re-estimate, cut lines, Step 7 lanes and waves), chief-architect (sequencing risk, wave 0 contract freeze, lane interfaces, technical debt accepted per phase), product-manager (value per phase, design-partner profile, scope cut decisions from the buyer's view, success metrics), project-shipper (milestones, demo script, launch/readiness checklists per phase, Phase 2 cloud cutover plan). Each writes `docs/council/roadmap/<member>.md`. Chair synthesizes `SYNTHESIS.md` + `ROADMAP.md`.
